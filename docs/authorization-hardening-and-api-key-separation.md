# Docmost 授权收紧与 API 密钥分离设计

## 1. 目标

本次升级同时解决两类问题：

- 将页面、模板、验证流程和实时连接统一纳入服务端资源授权，避免只校验登录或工作区造成同租户越权。
- 保留同一套 `api_keys` 表和签发服务，但从产品和数据约束上彻底分离 REST API 密钥与 MCP 密钥。

本文件也是本次实施清单。实现中发现的新缺陷必须追加到“缺陷复盘”，完成项必须在同一提交中勾选。

## 2. 安全原则

一次请求必须依次满足以下边界，任一层失败都应拒绝：

1. 凭据有效：JWT、API key 或 OAuth token 未过期、未撤销且类型正确。
2. 主体有效：用户、会话和工作区当前仍可用。
3. 范围有效：scope、空间授权和资源实际所属空间一致。
4. 资源有效：调用者对目标页面、模板、评论或子树拥有所需 read/write/manage 权限。
5. 业务有效：看板等扩展策略允许本次页面操作。

`workspaceId` 只用于租户隔离，不能替代空间成员、页面限制或资源操作权限。

## 3. API 密钥模型

### 3.1 类型

`api_keys.key_type` 为不可为空且创建后不可变的枚举语义字段：

| 类型   | 允许 scope                                 | 空间模式            | 使用入口   |
| ------ | ------------------------------------------ | ------------------- | ---------- |
| `rest` | `rest:read`、`rest:write`                  | 仅 `all`            | `/api/...` |
| `mcp`  | `mcp:read`、`mcp:write`、`mcp:destructive` | `all` 或 `selected` | `/mcp`     |

禁止一个密钥同时拥有 REST 与 MCP scope。服务层和数据库 CHECK 约束必须同时执行该规则。

### 3.2 数据迁移

- 只含 REST scope 的现有密钥归类为 `rest`。
- 只含 MCP scope 的现有密钥归类为 `mcp`。
- 同时包含两类 scope、为空或包含未知 scope 的密钥立即软删除。
- 被软删除密钥的既有 JWT 在下一次请求时因数据库回查失败而失效。
- 不保留兼容密钥，也不允许通过更新接口切换类型。

迁移 `down` 只撤销结构约束，不能恢复已经撤销的混合密钥。

这是一次有意的安全收紧，不提供兼容期。升级后，使用混合 scope、空 scope、未知
scope 或非法空间模式的旧密钥会立即失效，管理员和用户需要分别创建 REST 密钥与 MCP
密钥。撤销动作不可通过回滚迁移恢复，避免已经判定为不安全的凭据重新生效。

### 3.3 前端信息架构

账户设置：

```text
REST API 密钥
MCP 连接
├── MCP 密钥
├── OAuth 应用
└── MCP 活动
```

- REST 页面不展示 MCP 地址或空间隔离控件。
- MCP 密钥页面只展示 MCP scope、空间范围和 MCP 服务地址。
- OAuth 只出现在 MCP 连接分组。
- 所有列表请求显式携带 `keyType`，创建请求必须显式携带 `keyType`。

## 4. 资源授权规则

### 4.1 页面验证

- 查看详情和列表：必须能查看对应页面。
- 创建、更新、删除和提交审批：必须能编辑对应页面。
- 通过、拒绝和标记过期：必须是当前配置的审核人，并且仍能查看页面。
- 审核人必须是当前工作区的有效用户。
- 列表分页不能先泄露无权页面再由前端隐藏。

### 4.2 模板

- 模板详情、更新、删除和使用都必须校验来源模板权限。
- 工作区管理员始终按现有 CASL 规则管理模板。
- 普通成员只有在工作区设置允许且拥有目标空间权限时才能创建或管理模板。
- 使用模板创建页面必须另外校验目标空间创建权限和父页面编辑权限。

### 4.3 页面子树

- 删除或恢复页面时，对本次实际修改的每个后代页面校验编辑权限。
- 任一后代不允许时整次操作失败，不执行部分子树修改。
- 资源校验与子树写入应在同一事务或等价锁定范围内，避免检查后资源关系变化。

### 4.4 页面权限主体

- 被添加的用户和用户组必须属于目标页面的工作区。
- 用户必须未删除、未停用。
- 禁止建立跨工作区主体引用；接口错误不能泄露其他工作区主体是否存在。

## 5. 撤权与实时连接

### 5.1 HTTP 与 MCP

- 每次请求重新校验用户、工作区、凭据和有效空间。
- 空间移除只撤销该空间的有效访问；凭据仍可用于其余有效空间。
- 用户停用或删除会永久撤销其 API key、OAuth authorization、refresh token 和未消费授权码。
- 已经开始执行的请求不保证中途终止，但下一次请求必须失败。

### 5.2 Socket.IO 与协作连接

- 新连接必须验证当前用户、工作区和未撤销会话。
- 协作 token 必须绑定登录 session，不能在 session 撤销后继续重连。
- 用户停用、会话撤销、空间或群组成员变化必须通过现有 Redis 能力传播到所有实例。
- 已有连接收到撤权后应断开或离开对应空间；文档持久化前必须再次校验写权限。

### 5.3 缓存

- 权限缓存使用 revision/version 键或等价机制。
- 撤权提交后旧查询即使晚到，也只能写入旧 revision，不能重新激活旧授权。
- 禁止使用 Redis `KEYS` 扫描实现失效。

## 6. 工作区状态

- `deletedAt` 非空的工作区不可建立新请求或实时连接。
- `status = suspended` 的工作区不可建立新请求或实时连接。
- 历史和自托管工作区的 `status = null` 继续视为可用，避免升级后锁死现有实例。
- 需要读取已删除工作区的管理/恢复代码继续使用不带 active 过滤的专用查询。

## 8. 缺陷复盘

- 页面验证原先先分页再过滤，既会造成空页，也可能泄露不可访问资源的数量特征。现改为在
  数据库查询阶段加入统一的页面访问谓词，游标只基于可见记录；标题和空间搜索也在同一查询
  中执行。
- 会话创建与用户停用存在锁顺序不一致风险，并且旧 ACCESS JWT 没有 `sessionId` 时可以绕过
  会话撤销。现在统一锁顺序，并强制 ACCESS JWT 绑定有效 session；旧登录会话升级后需要重新登录。
- 页面永久删除原先在授权检查后另开事务写入，存在页面树关系变化的检查时序窗口。现在锁定
  子树、逐项授权并在同一事务中删除。
- 页面永久删除提交后再直接投递附件清理任务，Redis 短暂不可用时可能永久漏清理。现在先在
  数据库事务中写入 queue outbox，再由定时调度幂等投递到 BullMQ。
- 权限缓存首次使用时没有 revision，导致缓存实际被绕过；并且撤权时需要避免旧查询覆盖新
  结果。现在初始化版本键，并在写缓存前后二次比对 revision。
- Redis Pub/Sub 不保存离线事件。Socket.IO 与协作服务除即时订阅安全事件外，每 30 秒还会
  从持久化数据重新校验用户、工作区、session、空间成员和页面权限，将漏事件窗口限制在
  30 秒内；HTTP 和 MCP 请求仍逐次校验。
- 客户端曾可向树事件通道发送看似权威的新增、移动和删除消息。现在客户端只允许请求刷新
  根树，具体变更只能由服务端业务操作产生并广播。
- MCP 关闭或处于只读模式时，密钥创建/更新原先仍可能保存不可用的写 scope。现在前端禁用
  不合法选项，服务端独立拒绝，不能通过直接调用接口绕过。
- 迁移测试文件曾与生产迁移放在同一目录，Kysely 会把测试文件误识别为迁移。真实 PostgreSQL
  演练发现后已将测试移到独立目录，并重新验证完整迁移链。
- 页面树删除和恢复原先对每个后代分别查询空间和页面权限，深层树会长时间持锁。现在按空间
  批量计算整棵子树的可见/可编辑集合，仍保持任一节点无权则整次回滚。
- 独立复核确认 REST 与 MCP 已在签发、更新、认证、列表、前端入口和审计字段上分离；未保留
  混合密钥兼容入口。

- 服务端：110 个测试套件、661 个测试和 1 个快照全部通过。
- 客户端：36 个测试文件、199 个测试全部通过。
- ESLint：0 个错误；13 个既有警告与本次改动无关。
- 版本一致性：所有 package 版本均为 `26.06.20.0`。
- 生产构建：服务端、客户端和编辑器扩展全部通过。
- 数据库：在临时 PostgreSQL 上从空库执行完整迁移链，包含 API key 类型迁移和 queue outbox
  迁移；另用 REST、MCP、混合、空、未知 scope 和非法空间模式夹具验证分类、撤销及授权记录
  清理结果。
- 界面：验证桌面、移动端深色模式、旧路由重定向、MCP 关闭、只读和读写模式，无横向溢出或
  控件遮挡。

## 10. 已知边界

- 跨实例 Redis 故障没有在真实多节点生产拓扑中演练；持久化状态的 30 秒周期复核用于限制
  Pub/Sub 漏事件造成的授权延迟。
- 大型页面子树仍需锁定并批量验证所有后代，耗时会随节点数增长；已消除逐节点权限查询，但
  原子授权本身的线性成本不能省略。
- 被迁移撤销的非法或混合密钥不会自动重建，升级后必须由用户创建用途单一的新密钥。
